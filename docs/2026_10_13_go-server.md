# Go server: conventions, Yjs from Go, migration (concept, 2026-10-13)

Temporary working note, the Go answer to section 4 ("Server language") of `2026_10_13_gitlab-projects.md`. Distill into
40_architecture/09 and 11 "Open work" and delete once decided. Legend: (v) verified today in code (cloned repos) or on
the web, (r) recalled, check before relying on it.

## Decisions (user, 2026-10-13)

- **Server in Go**, conventions after `sandstorm/dashica` (§ below).
- **CRDT stays Yjs; the Go server uses `reearth/ygo`.** No fallback (no yrs, no Node sidecar): if ygo falls short,
  fix it in ygo / contribute upstream.
- The browser client stays as it is (`HocuspocusProvider`, room protocol).
- **Server-side Typst compile (if we build it) runs via wazero** (WASI build of the engine, `go:embed`), not the
  `typst` CLI (§3).
- **Logging: zerolog** as in dashica. ygo's core packages (`crdt`, `sync`, `awareness`) don't log (v): no slog bridge.
- **Go module at the repo root**, like dashica (`go.mod` next to `package.json`); the code lives under `server/`
  (`server/cmd/zwiebelfisch/`, `server/lib/<pkg>`, as dashica). The built app is embedded by a small package at the
  repo root (`go:embed` cannot reach parent folders).
- What ygo says about itself (pasted by the user): binary-compatible with Yjs (V1 and V2 update formats byte for byte,
  y-protocols sync handshake and awareness); a byte-level conformance suite generated from yjs@13.6.30 and a
  differential convergence fuzzer run in CI; a Hocuspocus-compatible WebSocket server, horizontally scalable through a
  Redis-backed cluster relay; versioned persistence (including a cgo-free SQLite store), snapshots, a `ygo-server`
  binary; embeds on iOS/Android via gomobile, no cgo anywhere.
- Spike question answered (v): **ygo's own server can not carry our room layer.** No user per connection; stateless
  messages don't name the sender; server-side edits lose attribution (no origin per connection); content is served
  before auth (initial sync before PermissionDenied); the room comes from the URL path, not multiplexed per frame
  (the provider shares one socket for many rooms); no SyncStatus acks. Our room layer (`server/lib/collab`) is ~730
  lines (v).

## 0. Short answer

- **Yjs in Go works now**: two pure-Go Yjs ports are listed as *completed* ports in the Yjs docs (v: docs.yjs.dev
  "Ports to other languages": `reearth/ygo`, `Deln0r/ygo`). Use **`reearth/ygo`'s CRDT, sync and awareness packages**
  inside our own small Hocuspocus-protocol room layer (~730 lines in the spike (v)), behind one wrapper package (`server/lib/ydoc`).
- The client stays unchanged: `HocuspocusProvider`, the room protocol, the e2e specs.
- Biggest risk: the ports are ~3 months old and mostly single-author. The existing Playwright e2e suite plus Yjs-generated
  fixtures are the gate. Spike first (1-2 days), then decide.
- Node stays only as the **frontend build tool** (the widget is TypeScript/Vite). It is no longer a runtime.

## 1. dashica conventions → ours

Cloned `github.com/sandstorm/dashica` (v). dashica is a *library* that apps embed (`dashica.New(fs)` + `RegisterDashboard`),
rendered on the server (templ + Alpine). We are an *app* with an SPA, so a few choices differ.

| Topic | dashica uses (v) | We'd use |
|---|---|---|
| Layout | `dashica.go` (root package, `New()`), `lib/<pkg>` (alerting, clickhouse, config, httpserver, logging, testutil, util), `cmd/dashica-gen`, `public/embed.go` | Go module at the repo root (decided), code under `server/`: `server/cmd/zwiebelfisch/main.go`, `server/lib/<pkg>` (as dashica; no `internal/`: nobody imports the server) |
| HTTP router | stdlib `http.NewServeMux` + a small validating `HandlerCollector` (prefix nesting) | stdlib `ServeMux` with Go 1.22 patterns (`GET /api/projects/{id}/branches`). No framework |
| Handlers | structs with deps (`queryAlertsHandler{logger, manager, devMode}`) implementing `http.Handler` | same |
| Config | koanf v2: defaults map → `<name>_config.<APP_ENV>.yaml` → env (`SECTION__KEY` → `section.key`) → struct with `koanf:` tags, `validateConfig` | same: `typst_config.yaml` + env `GITLAB__URL`, `GITLAB__CLIENT_SECRET`, … (secrets via env / `mise.local.toml`) |
| Logging | zerolog (+ lumberjack file rotation, ConsoleWriter on stdout), field-name constants (`event_dataset`, `event_module`) | zerolog with the same field constants. ygo's core packages don't log (v) |

| Docker / release | docker-compose only for dev deps (ClickHouse); goreleaser workflow commented out; no Dockerfile | multi-stage Dockerfile (node: build app → go: build → `distroless/static`), one binary with the app embedded |

## 2. Yjs from Go

### What the server must do with the Y.Doc (as the TypeScript server's `gitlab-room.ts` did, (v))

| Need | Detail |
|---|---|
| Hocuspocus wire protocol | The client is `@hocuspocus/provider` 4.7 (`src/extensions/collaboration/model/model.ts`). Frame = `VarString(room)` + `VarUint(type)` + payload; types 0 Sync, 1 Awareness, 2 Auth (token / PermissionDenied / Authenticated), 3 QueryAwareness, 5 Stateless, 7 Close, 8 SyncStatus, 9 Ping, 10 Pong (v: spike, against the real provider). The provider has **no** 4 SyncReply / 6 BroadcastStateless (ygo's list). Pong is a bare 1-byte frame (no room). The provider sends Auth, SyncStep1 and Awareness at once: the server queues a room's messages until its Auth is handled (v). "No unsynced changes" needs a SyncStatus (8, value 1) ack per applied update (v). It closes after 30 s of silence, so awareness is echoed to the sender too (v). PermissionDenied (reason `permission-denied`) leaves the socket open (v) |
| Access check on join | Auth message (token) or the session cookie of the upgrade request → user; refuse with 4401 |
| Load GitLab content into the doc | `files: Y.Map<path, Y.Text>`, `assets: Y.Map<path, sha \| Uint8Array>`, `meta` map with JSON values (`base: Record<path,string>`, `changes`, `conflict`, numbers, null) |
| Read the texts to commit | `Y.Text.toString()` of every file; assets as sha or bytes |
| Merge upstream as minimal edits | `Y.Text.delete/insert` at **UTF-16** offsets, inside one transaction with the room as origin |
| Attribute edits | `doc.on('update', (u, origin))`: the origin is the connection, so the room knows the user |
| Stateless | receive `gitlab:save` from one connection; reply to that one or broadcast to all |
| Lifecycle | load on first connection, debounced store (2 s), "last user left" → auto-commit after 20 s, unload |
| Persistence | the whole doc state per room (SQLite) |

Neither port's repository runs a real `@hocuspocus/provider` in CI (v: no such npm dependency). Our e2e suite would be
the first. Volume (reearth: 210 KB changelog in 3 months) suggests heavy AI-assisted development (r). Strong tests, but
no long production record. That is why the CRDT library stays behind `server/lib/ydoc`.

**b) yrs**: the most trustworthy CRDT, but the worst Go ergonomics (cgo via yffi, or yffi as `wasm32-wasip1` in
wazero). Rejected (user: no fallback).

**c) Dumb relay**: storage works without a CRDT (append frames, replay all on SyncStep1). But **compaction needs
Yjs logic** (`Y.mergeUpdates` decodes the struct format), unless a client uploads a snapshot now and then. The real
problem is commits: the server needs the file texts. So the committing user's browser would build the commit
(`commit-actions.ts` and `merge.ts` are pure TS already) and send it through the server's GitLab proxy with that
user's token.

| + | − |
|---|---|
| no CRDT in Go at all | auto-commit after the last user left is impossible (no client there) |
| commits naturally as the saving user | concurrent saves/merges need a leader (e.g. lowest awareness clientID): new distributed logic |
| | `meta` (base, changes, conflict) written by clients: one buggy or malicious client corrupts the room's base |
| | ~1300 lines of room logic move into the app shell. Webhook merges wait until someone opens the room |

Not recommended. It trades a library risk for a design that is harder to get right.

**d) Sidecar**: keeping today's Hocuspocus server as a Node sidecar (Go does OAuth, the API, app serving). Rejected
(user: no Node, no fallback). y-sweet (Rust) has its own client/auth protocol: the client and the GitLab
logic would both change. Mention only.

### Recommendation

Option a with `reearth/ygo` (org-backed, listed, exported `crdt`/`sync`/`awareness` packages, most commits). Use our own
Hocuspocus layer, not its server: we need the user per connection, the transaction origin per connection, and replies
to one peer. Wrap the CRDT so nothing else imports it:

```go
// server/lib/ydoc: the only package importing github.com/reearth/ygo. Swap here for yrs if ever needed.
type Doc struct{ d *crdt.Doc }
func (d *Doc) HandleSync(msg []byte, origin any) (reply []byte, err error) // sync.ApplySyncMessage
func (d *Doc) State() []byte                                              // for storage
func (d *Doc) OnUpdate(fn func(update []byte, origin any)) (stop func())
func (d *Doc) Texts(m string) map[string]string                           // files → path → text
func (d *Doc) Value(m, key string) any                                    // meta values as map[string]any/[]any
func (d *Doc) Write(origin any, fn func(w *Writer))                       // one transaction
// Writer: SetText(m, path, text), Edit(m, path, from16, to16, insert), Set(m, key, v), Delete(m, key)
```

```go
// server/lib/collab: Hocuspocus framing, one room per name, rooms own a ydoc.Doc + awareness.
func (c *conn) handle(frame []byte) error {
	d := lib0.NewDecoder(frame)
	name, typ := d.ReadVarString(), d.ReadVarUint()
	switch typ {
	case msgAuth: // token → c.user via Authenticate(r, name, token); then reply Authenticated and join the room
	case msgSync, msgSyncReply:
		reply, err := c.room.doc.HandleSync(d.Rest(), c) // origin = conn → editors know the user
		if typ == msgSync && reply != nil { c.send(name, msgSync, reply) }
	case msgAwareness:      c.room.awareness.Apply(d.ReadVarBytes(), c); c.room.broadcast(frame, c)
	case msgQueryAwareness: c.send(name, msgAwareness, c.room.awareness.Encode())
	case msgStateless:      go c.room.ext.Stateless(c, d.ReadVarString()) // gitlab:save
	}
	return nil
}
```

Details to get right: `Edit` takes UTF-16 offsets (Go strings are UTF-8, and `merge.go` must convert). Y.Map values
must be `map[string]any`/`[]any`, not structs (marshal through JSON). Timestamps above 2^31 are encoded as float64,
as lib0 does ((v) ygo's `WriteAny` mirrors lib0). Run each room's operations through one goroutine/mutex, like
today's `run` queue.

Risks:
- **CRDT divergence** in a young port means silent data loss. Mitigations: the wrapper, e2e on every change, fixture
  tests generated by yjs, a nightly randomized differential test (Node yjs vs Go on the same edit script), version pins.
- Hocuspocus protocol drift when `@hocuspocus/provider` is upgraded (we now own the framing): pin it, e2e.
- UTF-16 vs UTF-8 offsets in merges and conflict ranges (`ConflictRange` is UTF-16).
- Duplicated room protocol (TS + Go): small and stable, covered by the shared fixture.
- Two languages in `server/` workflows: Node remains for the frontend build and e2e, not as a runtime.

## 6. Spike (steps 0 and 1, merged 2026-10-13)

Built (v): `server/lib/{ydoc,collab,store,config,logging}`, `server/cmd/zwiebelfisch`, mise tasks `server:go:dev` /
`server:go:test`; Yjs fixtures both directions (`server/testdata/gen-fixtures.ts`); the real `HocuspocusProvider`
in-process (`server/testdata/hocuspocus-clients.ts`, `TestRealHocuspocusProvider`). Wire protocol findings: §2.

ygo caveats (v1.51.9, not v1.9.0; (v)):
- Read accessors take the document lock that `Transact` holds: they deadlock inside a transaction. `ydoc.Write`
  checks before transacting.
- `YMap.ForEach` skips nested types: use `Keys` + `Get`.
- No public awareness remove: `ydoc.Awareness.Remove` builds the null-state update by hand.
- Core packages don't log (no slog bridge needed).
- Fast version churn (v1.9.0 → v1.51.9 within weeks): pin exactly, run fixtures and e2e on every bump.

Not yet:
- `TestServerBinary` needs a real port (skips in the sandbox): run locally.
- The Playwright collaboration and GitLab specs against the Go server (need ports: not run yet).
- Config YAML file not read yet (env only).
- Stale presence expiry (Hocuspocus drops awareness after 30 s without update): open.
- Store: same SQLite file, new `rooms` table; old Hocuspocus rooms are not read (fine: no backwards compat).
- ~~Empty `TYPST_COLLAB_TOKEN` disabled the check~~ Gone: the shared token was replaced by the sign-in (below).

Step 2 (GitLab rooms), built (v) with the decisions of `2026_10_13_gitlab-projects.md`:
- `server/lib/gitlab`: `Rooms` is a `collab.Extension` (rooms `gitlab:<project>@<branch>`; `gitlab` = `Options.ID`, the
  provider id, also in the webhook path `/<id>/webhook`) and the `http.Handler` of `/rooms/{room}/files/{path...}` and
  the webhook (`X-Gitlab-Token`, constant-time compare). `Repository` (Head, Tree, Blob, Commit with `ExpectedHead` →
  `ErrConflict`) is the provider seam; `api.go` is GitLab's REST behind it (no `author_name`: the bot token's user is
  the author; every editor is a `Co-authored-by:` trailer, also the saver if they edited). `.typ` files are read as
  blobs (no per-file `files` call, no `lastCommits` in `meta`).
- GitLab's commit API cannot require "the branch is still at X" (research §3, (r)): `Commit` compares the head first and,
  when GitLab refuses an action, again (moved → `ErrConflict` → diff3 merge + retry). A push landing in between that
  GitLab does not refuse ends up under our commit; the room sees `parent ≠ base` and merges it in.
- `server/lib/diff3`: own port of node-diff3 (`epiclabs-io/diff3` only returns marked-up text, no regions with
  indices, which the conflict ranges need). 400 random cases from node-diff3 3.2.1 itself are the test fixture
  (`server/lib/diff3/testdata/node-diff3.json`; its generator went with the TypeScript server).
- `collab`: `Extension.Open(room, doc)` runs on the room's goroutine before anyone joins (the GitLab load); a
  `Handler` gets stateless messages, `Left(ctx)` keeps the room loaded (joinable) until it returns (the 20 s
  leave delay + auto-commit), `Close` on unload; `Room.Do` for the document from other goroutines; `Peer.Name()`
  falls back to the awareness `user.name`. `ydoc` got plain map values (`Values`, `Writer.Set`).

### @automerge/automerge 3.5.0 (browser)
- **Size:** `automerge.wasm` is 3.64 MB raw and **1.14 MB gzip** **[v]**. By comparison, `yjs.mjs` is **63 KB gzip** **[v]**, so Automerge is about 18x larger. The wasm loads asynchronously (`initializeWasm`, `isWasmInitialized`) **[v]**. That fits our lazily loaded collaboration chunk, but it adds a second large wasm next to the Typst engine.
- **Text API:** `splice(doc, path, index|Cursor, del, text)` and `updateText(doc, path, newText)` (diff-based) **[v]**. Remote changes arrive as patches (`patchCallback`: splice and del with path), which replace our Y delta→TextChange conversion **[v API / r shape]**.
- **Stable cursors:** `getCursor(doc, path, pos, move?)` and `getCursorPosition(doc, path, cursor)` **[v]**. These are equivalent to `Y.createRelativePosition*`, so remote cursors map 1:1. Marks exist (`mark`) but we don't need them.
- **Performance and memory:** 3.x keeps the columnar compressed form at runtime. The Moby Dick paste dropped from 700 MB to 1.3 MB, and loads with long histories got much faster **[v, blog]**. Automerge keeps the **full history forever**, with no GC or compaction of ops (`save()` only compresses) **[r]**. That is fine for documents of about 100 KB with many keystroke edits. Yjs is still faster per keystroke **[r, crdt-benchmarks]**. Each local edit is an `A.change` call that returns a new immutable doc **[r]**.

### Sync, presence, server
- **Protocol:** Automerge sync is pairwise. Each peer has a `SyncState`, and peers exchange heads, Bloom filters and missing changes until both sides converge **[r]**. Yjs instead broadcasts each update and uses state vectors on connect. For a Go hub this means **one SyncState per (room, client)**. A message received from client A is applied to the server doc, and then `GenerateMessage` runs for every other client. This takes about 150 lines of Go and holds the full doc, which we need anyway for commits and GitLab merges. automerge-repo (JS) has its own WebSocket adapter protocol (CBOR, join/peer/sync/ephemeral) **[r]**. Doing it by hand in Go is simpler than reimplementing automerge-repo.
- **Presence:** automerge-repo has "ephemeral messages" **[r]**. We already have our own presence and remote cursors over awareness, so we keep those as our own JSON messages on the same WebSocket, and cursors become Automerge `Cursor` strings.
- **Attribution:** today the server finds the editor of a change from the Y transaction origin (`gitlab-room.ts:148`). With Automerge, every change carries an actor id and an optional message, so mapping actor to user gives co-author attribution for free **[v API]**.

### Fit / migration in this repo
Yjs code reaches into almost every collaboration file **[v]**:
- `text-binding.ts` (86 lines): the observe/delta logic becomes patches and splice.
- `shared-project.ts`, `shared-assets.ts`, `shared-main-file.ts`: the `Y.Map` of `Y.Text`/meta becomes paths in a single doc.
- `remote-cursors.ts`: relative positions become Automerge cursors.
- `gitlab-source-control.ts`: the meta map and stateless messages.
- `model.ts`: `HocuspocusProvider` becomes our own sync client.
- `in-process.ts` (test wiring).
- The public option `{ doc: Y.Doc; awareness }` in `collaboration.ts`.

On the server, Hocuspocus, sqlite and Yjs (1,865 lines) are replaced in a Go rewrite either way. **Estimate:** the client side is about 1–1.5 weeks including tests (`convergence.test.ts` etc.). The server is the same Go work as with Yjs, plus the per-peer sync loop. Our own architecture (shared texts plus our own binding, no editor bindings) makes the switch technically possible.

**Risks:**
1. automerge-go is dormant and stuck on the 2.x core.
2. 1.1 MB more wasm in the browser.
3. History is never discarded.
4. The cgo/glibc build.
5. Code-point vs UTF-16 indices.
6. We lose the provider ecosystem (Hocuspocus, y-* tooling).

### Loro
Go bindings exist:
- **aholstenson/loro-go:** cgo, prebuilt static libs for macOS/Linux arm64+amd64 and Windows amd64, no Rust toolchain needed. v0.5.0 from 2026-06-24 wraps Loro 1.13.6, while npm has 1.16.4. It says "API is pre-1.0", 22 stars **[v]**.
- **Deln0r/loro-go:** a pure-Go implementation of the wire format, 6 stars **[v]**.

loro-crdt's wasm is **1.12 MB gzip** **[v]**. Loro has fast text, stable cursors, built-in ephemeral presence, history and shallow snapshots that trim history **[r]**. The core is the youngest of the three. Both Go options are small, single-maintainer projects.

### Recommendation for this project
| Option | Go server | Browser | Verdict |
|---|---|---|---|
| **Yjs + Go** | Pure-Go ports exist: reearth/ygo (since 2025-04, 61 stars, active) and Deln0r/ygo (claims V1/V2 wire compatibility, 92 stars) **[v exists / maturity unverified]**. | 63 KB, no change to the client | **Recommended**: the client stays as it is, and only the server language changes |
