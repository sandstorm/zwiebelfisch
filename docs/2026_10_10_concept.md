# Concept: an embeddable Typst editor for non-technical users

_2026-10-10. Based on [2026_10_10_prior-art-research.md](2026_10_10_prior-art-research.md)._

## Goal

Make Typst usable by people who would otherwise use OnlyOffice or Word, without giving up what makes
Typst good: plain-text source in git, arbitrary Typst always works, diffs stay readable.

The editor is a **framework-agnostic, embeddable JS widget**. It has two panes:

- **Left:** an editing view. This is either the **Source** view (CodeMirror 6) or the **Visual** view
  (a ProseMirror WYSIWYG view). Both edit the same text.
- **Right:** a live **Preview** of the compiled document. Clicking in the preview highlights and
  scrolls to the source range in whichever editing view is active.

## Non-negotiables

1. **The Typst text is the only source of truth.** Every other representation is derived from it:
   the CodeMirror document, the ProseMirror document, the preview and the outline.
2. **Arbitrary Typst always works.** Anything the Visual view does not understand is shown as an
   opaque *raw Typst* node. You can edit its source inline, and it round-trips byte for byte.
3. **Edits touch only what changed.** An edit in the Visual view becomes a minimal text edit to the
   node that changed. Formatting, comments and whitespace elsewhere stay byte-identical. This keeps
   git diffs clean and makes collaboration on the text sound.

## What exists already, and the gap

Every open-source Typst web editor (TeXlyre, TOSS, collabst, TypstDrive) uses the same pattern:
CodeMirror 6, typst.ts in a Web Worker, and Yjs `Y.Text` per file. None of them has a WYSIWYG view
that keeps the text as the source of truth. The Typst WYSIWYG attempts (ortic/typst-wysiwyg, TyX)
make a JSON model canonical and *generate* Typst from it. The markdown WYSIWYG editors (Milkdown,
Quarto, Tiptap) re-print the whole document and normalise its formatting. Overleaf's Visual Editor is
the right philosophy (the text stays canonical), but it decorates CodeMirror rather than giving a real
document model. **A source-anchored ProseMirror projection over Typst is the new part of this
project.**

## Architecture

```
                       ┌──────────────────────────────┐
                       │ TypstDocument (deep module)  │
   CodeMirror view ◄──►│  text (later: Y.Text)        │◄──► Collab provider (later)
                       │  incremental Lezer CST       │
   ProseMirror view ◄─►│  change events + origins     │
                       └──────────────┬───────────────┘
                                      │ text (debounced)
                                      ▼
                       ┌──────────────────────────────┐
                       │ Preview (deep module)        │
                       │  Worker: typst.ts compiler   │
                       │   + incremental vector delta │
                       │   + jump_from_click (wasm)   │
                       │  Main: renderer → SVG        │
                       └──────────────────────────────┘
```

Each module has a small interface and hides a lot of complexity, in the spirit of
*A Philosophy of Software Design*:

| Module | Interface (approx.) | Hides |
|---|---|---|
| `TypstDocument` | `text`, `tree`, `change(edits, origin)`, `onChange(fn)` | text storage (string now, `Y.Text` later), incremental parsing, origin tagging so views don't echo their own edits |
| `SourceView` | `mount(el)`, `reveal(range)` | CodeMirror setup, Typst language support, two-way binding with the document |
| `VisualView` | `mount(el)`, `reveal(range)` | the CST → ProseMirror projection, the minimal write-back, raw Typst nodes with nested CodeMirror, the toolbar commands |
| `Preview` | `update(source)`, `onJump(fn)`, `reveal(range)` | the worker protocol, typst.ts compiler and renderer, fonts, packages, incremental deltas, click hit-testing and span → offset resolution |
| `TypstEditor` | `createTypstEditor(el, opts)` / `<typst-editor>` | composing the above, layout, switching between views |

### Parsing: `codemirror-lang-typst/lezer`

This is a pure-JS, incremental Lezer grammar for Typst 0.15 that uses typst-syntax's node names. It
keeps every byte of the source (trivia included). One tree drives syntax highlighting, the outline
and the ProseMirror projection. We will cross-check it against the real `typst-syntax` parser in
tests if it ever drifts.

### The Visual view: a source-anchored ProseMirror projection

- **Text → PM.** Walk the CST. Supported constructs map to PM nodes and marks: paragraphs,
  headings, `*strong*`, `_emph_`, bullet lists and numbered lists, links, inline raw/code, math (as an
  atom), and later tables, figures, images and footnotes. Every PM node records the source range it
  came from. Everything else (`#set`, `#let`, `#show`, function calls we don't model, and so on) becomes a
  `raw_block` / `raw_inline` atom that holds the verbatim source.
- **PM → text.** When a PM transaction happens, find the top-level blocks that changed. Re-print
  only those, reusing the original source slice for every unchanged child. Diff the old slice
  against the new one and apply the smallest text edit to `TypstDocument`. Unchanged regions are
  never rewritten.
- **Text changes from elsewhere** (the Source view, a remote peer). Re-project only the affected
  top-level blocks and replace them in PM inside one transaction, tagged so it does not echo back.
- **Tests:** the property `project(src) → print === src` holds for a large set of fixtures. Randomised
  edit tests check that only the edited span changes.

### Preview and click → source

- typst.ts in a **Web Worker**: incremental compilation that produces vector-IR deltas. The renderer
  on the main thread merges the deltas and patches the SVG.
- **Click → source:** the stock typst.ts web compiler cannot do this, because its span plumbing is
  unused. We will build a small wasm-bindgen crate on the typst.ts world with
  `typst_ide::jump_from_click(world, doc, frame, point)` and `jump_from_cursor`. This is the same
  approach tinymist and wasm-typst-studio-rs use. The client sends `{page, x, y}` in points and gets
  back a source byte range.
- **Cursor → preview:** `jump_from_cursor` gives page positions, which we scroll to and flash.

### Typst version

Typst 0.15 (typst.ts `0.8.0-rc3`, pinned exactly). It matches the Lezer grammar and current Typst.
The CLI is pinned to the same Typst version through mise.

## Collaboration and the server (later)

- **Shared state:** Yjs, one `Y.Doc` per project, with `Y.Map<path, Y.Text>`. CodeMirror binds through
  `y-codemirror.next`. **ProseMirror never syncs directly.** It stays a projection of the local
  `Y.Text`, so there is only one source of truth even in a collaborative session. Remote cursors
  travel in Yjs awareness as text positions and are mapped into both views.
- **Server:** Hocuspocus (Node). It handles auth hooks, debounced persistence of Yjs updates
  (Postgres or S3) and Redis scale-out.
- **GitLab:**
  - *Load:* on first open, read the repository tree and files through the GitLab API, seed the
    `Y.Text`s and remember `baseSha`.
  - *Save:* "Save version" (or idle or last-client-leaves) creates one commit with
    `POST /projects/:id/repository/commits` and `last_commit_id = baseSha` for optimistic concurrency.
    If upstream moved, do a 3-way merge and apply it to `Y.Text` as minimal edits. An alternative is a
    branch per session plus a merge request, which fits a "publish" mental model.
  - *Assets* (images, fonts) are stored by reference (path plus SHA), never inside Yjs.
- The widget takes the provider as a parameter (none, IndexedDB or Hocuspocus), so the same widget
  works standalone, offline or collaboratively.

## Milestones

1. **Skeleton:** the widget renders the preview from a source string. Playwright tracer test.
2. **Source view:** CodeMirror with Typst highlighting, live preview while typing (worker,
   incremental).
3. **Visual view v1:** the ProseMirror projection for paragraphs, headings, strong/emph and lists,
   plus raw atoms. Minimal write-back. Round-trip unit tests.
4. **Click → source:** the wasm jump crate, highlighting in both views, cursor → preview.
5. **Visual view v2:** a toolbar (bold, italic, heading levels, lists), nested CodeMirror for raw
   nodes, links, images, tables.
6. **Workspace:** multiple files, assets, packages and self-hosted fonts.
7. **Collaboration:** `Y.Text`, a Hocuspocus server, GitLab load and commit.

## Engineering rules

- Tooling and versions come only from mise (exact pins). Every script is a mise task in `mise-tasks/`.
- Tests come first. Playwright covers user-visible behaviour and vitest covers the projection and
  round-trip logic.
- Code follows APOSD: deep modules, information hiding, comments for what is not obvious. Code
  quality is tracked with complexity metrics (see the `code-quality` skill).
